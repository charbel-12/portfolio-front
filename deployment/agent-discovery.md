# Agent discovery on Netcup + Nginx + Cloudflare

The portfolio exports static files. Nginx serves the origin; Cloudflare provides DNS and proxy/CDN services. The repository does not have access to either control plane. No production configuration or DNS records have been changed.

## Build and install

Run `npm run build`, `npm run test:discovery`, and `node scripts/verify-export.mjs`. Deploy the **contents** of `out/`, including `.well-known/` and `_markdown/`, to the existing document root. Deployment commands that copy only `out/*` may omit `.well-known` on Linux. Deploy the generated Markdown map together with the matching export.

Install these snippets outside the web root, for example under `/etc/nginx/portfolio/`:

- `nginx-agent-http.conf`
- `generated/markdown-map.conf` (regenerated by every build)
- `nginx-agent-server.conf`

Add these two includes inside `http {}`, in this order:

```nginx
include /etc/nginx/portfolio/nginx-agent-http.conf;
include /etc/nginx/portfolio/markdown-map.conf;
```

Merge `nginx-agent-server.conf` into the existing HTTPS `server {}`. Replace its current `location /` with the supplied one and preserve the existing document root, TLS, logging, compression, and security configuration. Ensure `index index.html;` and the normal `mime.types` include remain configured. Do not add a duplicate `location /`. Adapt existing regex locations so `.well-known` remains publicly accessible and the Markdown MIME rule runs before generic file rules. Other hidden files should remain denied.

Nginx `add_header` inheritance stops when a location declares its own `add_header` directives on many deployed versions. Preserve/repeat existing security headers in these locations, and preserve the discovery Link header in any customized homepage location. The supplied Markdown location includes Link explicitly for negotiated homepage responses.

Run `sudo nginx -t` before `sudo systemctl reload nginx`. Nginx is not installed in this development workspace, so the snippets require validation against the VPS's full configuration.

## Markdown and caching

An explicit acceptable `text/markdown` media range selects Markdown; `q=0` disables it. HTML is the default for absent Accept, browser Accept, or wildcards alone. When both formats are acceptable, this configuration prefers Markdown. GET and HEAD use the same routing. Query strings do not change the exported representation. Unrecognized routes return 404 rather than homepage content.

The export contains a Markdown representation of every English and Arabic page, derived from its rendered main content. JavaScript, styles, navigation controls, and SVG artwork are removed. No tokenizer is configured, so no approximate `x-markdown-tokens` value is advertised as an exact count.

Markdown responses include `Vary: Accept` and `Cache-Control: no-store`. In Cloudflare, bypass caching for content-page routes (all paths except explicitly cached immutable assets). Remove any Cache Everything or Edge TTL override for those routes and purge cached HTML when activating negotiation. Do not rely on `Vary: Accept` alone to partition Cloudflare's cache. Preserve existing long-lived caching for hashed `/_next/static/` assets. Cloudflare's own Markdown conversion is unnecessary when Nginx performs negotiation.

`next dev` serves the generated API/discovery files but does not emulate Nginx response headers or Markdown negotiation. The legacy `public/_headers` file is not used by Nginx.

## Published capabilities

| Capability | Resource |
| --- | --- |
| API catalog | `/.well-known/api-catalog` (`application/linkset+json`) |
| Public data | `/api/portfolio.json` |
| OpenAPI description | `/openapi.json` |
| Documentation | `/docs/api.md` |
| Static availability marker | `/api/status.json` (not live backend health) |
| Access guidance | `/auth.md` (anonymous reads, no registration) |
| Skills + SHA-256 digest | `/.well-known/agent-skills/index.json` |
| ARD manifest | `/.well-known/ai-catalog.json` (CORS `*`) |
| Browser tools | `get_portfolio_profile`, `find_portfolio_projects` |

WebMCP registration runs on mount only in browsers exposing `document.modelContext` or the legacy `navigator.modelContext`. Tools retrieve public information and do not contact anyone. Ordinary browsers continue without them. No polyfill pretends to provide native WebMCP support.

Content Signals live in `app/robots.txt/route.ts`: `ai-train=yes, search=yes, ai-input=yes`. Keep Cloudflare managed robots settings consistent so the edge does not add contradictory signals. The API, metadata, and skill index are regenerated before dev/build; edit `scripts/generate-discovery.mjs`, not generated files.

OAuth/OIDC discovery, OAuth protected-resource metadata, agent registration metadata, and an MCP server card are intentionally absent: the owner confirmed there is no OAuth provider or MCP endpoint. `/auth.md` explains anonymous access and does not claim an Auth.md registration flow.

## DNS

After deployment, publish the TXT record in `dns-discovery.zone` in Cloudflare. It points to the actual ARD catalog. It does **not** satisfy DNS-AID's SVCB entrypoint check.

DNS-AID remains pending a real agent/index protocol endpoint. Do not advertise `_a2a` or `_mcp` for this static portfolio. Once a compatible endpoint exists, publish a ServiceMode SVCB record under `_index._agents.charbelmdawar.com` with its actual target, supported ALPN identifiers, port, and endpoint parameters. Use numeric `keyNNNNN` names for experimental parameters agreed with the consumer; do not invent an assignment or label the ARD JSON document as a standardized DNS-AID index. The [current DNS-AID draft](https://datatracker.ietf.org/doc/draft-mozleywilliams-dnsop-dnsaid/) still leaves JSON organization-index encoding open.

For authenticated DNS discovery, enable DNSSEC at Cloudflare, then install Cloudflare's exact DS values at the domain registrar (Netcup if it is also the registrar). Verify a validating resolver returns the AD flag and no SERVFAIL before considering it complete. DNSSEC requires the registrar's delegation, not just a file or checkbox in this repository.

## Live verification

Run `node scripts/verify-agent-http.mjs https://charbelmdawar.com` after deployment. Check the origin as well as Cloudflare if their results differ. Test both GET and HEAD manually when changing Nginx configuration:

```sh
curl -I https://charbelmdawar.com/
curl -I -H 'Accept: text/markdown' https://charbelmdawar.com/
curl -i -H 'Accept: text/markdown;q=0, text/html' https://charbelmdawar.com/
```

The homepage must advertise Link, the negotiated response must use `text/markdown`, and q=0 must keep HTML. Confirm `/.well-known/ai-catalog.json` returns JSON and `Access-Control-Allow-Origin: *`. Check Cloudflare does not serve cached Markdown to a subsequent HTML request.

Implementation references: [RFC 8288](https://www.rfc-editor.org/rfc/rfc8288), [RFC 9727](https://www.rfc-editor.org/rfc/rfc9727), [WebMCP](https://webmachinelearning.github.io/webmcp/), and the [user-supplied discovery skills](https://isitagentready.com/.well-known/agent-skills/agent-skills/SKILL.md).
